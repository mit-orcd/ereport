# AGENTS.md — ORCD NFS storage discovery

The goal of this project is to discover NFS storage in the ORCD cluster by
mapping the automount LDAP tree to the underlying filesystem of each share.

Data is kept in `storage_discovery.sqlite3` and enriched with per-server filesystem
facts via `probe.sh` snapshots.

## Operating rules (in priority order)

1. **Ask before touching a server even when read-only.** Any command that reaches a cluster host
   — `ssh`, `ldapsearch`, `df`, `zfs list`, `showmount` - even read-only,
   even one host, needs the user's approval per batch. 
2. **Probes are read-only use raw commands. no python. no loops.** `probe.sh` holds the entire remote
   command set. Extend the snapshot by editing probe.sh; never run loops of
   ad-hoc ssh probes.
3. **Decisions are local.** `parse.py` (snapshots → DB) and `parse_ldap.py`
   (LDIF → DB) own every matching rule; collection never interprets. Fix
   bugs in the parsers and re-run them offline — a parser fix must not imply
   re-probing servers.
4. **Evidence over inference.** A column value must trace to
   `probe/<host>`. Unknown stays NULL; note the reason in the
   run output instead of guessing.
6. **Keep it dumb.** Stdlib only (uv project has zero deps), no CLIs, no
   flags beyond the documented modes (`--tag`/`--limit` on `--pull-facts`),
   every block readable on one screen.
7. **One change at a time, paced by the user.** Refactor and behaviour
   changes are separate steps from fleet runs; present results before
   extending scope.

## Flow

    discover.sh --ldap         → ldapsearch fetch → parse_ldap.py → DB
                                 (automount names cleaned to host names)
                               → inventory.yml (new hosts added)
    discover.sh --pull-facts   → probe.sh snapshot per inventory host
                                 (clush fanout, run_probes.sh)
                               → parse.py (offline) → DB (facts)
                               → inventory.yml (tags from facts)

## Gotchas the environment won't tell you

- `inventory.yml` is the probe host list, generated by `--ldap` (hosts) and
  `--pull-facts` (tags); a host that leaves LDAP is kept and reported, not
  deleted. A `shares.host` missing from the inventory is "unclassified" —
  tag it, don't probe it by accident.
- An LDAP name is not a host: `fstor010.ib` and `fstor010-p2.ib` are one
  machine (`##host` = `fstor010-mgmt`), stored as `fstor010`. `clean_host()`
  in hostlist.py drops `.ib/.inband/.lb`, `-mgmt` and `-p2`, and
  parse_ldap.py writes the result straight into `shares.host` — that is
  also the probe file and ssh target name. Never list LDAP names in the
  inventory, and never store one in the DB.
- The `.ib` / `.inband` / `.lb` suffixes describe how an export is
  published to clients, not how we reach the filer — never turn them into
  a network tag. Every probe is one ssh to `root@<box>` from the clush
  fanout; any jump the filer needs belongs in ssh config, not the script.
- `probe/<host>` is the only snapshot name; parse.py reports any file
  whose name is not an inventory host as ignored.

- Filer hosts accept only xcat's root key — ~/.ssh/config's filer stanza
  (`Host eofe-data* fstor* hstor* …`) supplies `ProxyJump xcat`, so
  `run_probes.sh` just runs `root@<filer>`; the same `root@<filer>` from a
  vantage without that stanza fails auth. LDAP reads go via `AUTOMOUNT_SSH`
  (default `root@core017`).
- The automount values in the local export tree are *export aliases*: newer
  filers present `/data`, `/data1…` roots via showmount, hiding
  `/data1/<…>`-shaped local dataset paths. `parse.py` re-roots candidates
  with the export root from the snapshot; short paths get NULL not errors.
- Runtime export table (`##exports`) ≉ `/etc/exports` (`##exportfile`): the file
  holds only static `fsid=0, crossmnt` root frames — per-dataset shares are
  injected at mount time (ZFS `sharenfs`), and legacy filers (eofe-*) may keep
  the file empty while everything is runtime-managed. `##exports` is the
  matching source; `##exportfile` corroborates only.
- Pool wildcard shares end in `&`; they resolve to the parent dataset
  (`/pool/00N/&` → `/data1/pool/008`).
- `leaf` is about shares, not zfs: 1 when no other share's local path
  (`local_fs`, or `share` when that path is the local mountpoint) sits
  beneath it, 0 when one does.  A filer's `/` under per-directory shares
  is 0 (16 xfs rows today, plus fstor001's `/software/community/001`);
  pool wildcards stay 1 because nothing else covers their children, so
  dropping every `leaf = 0` row never loses a byte.  Re-exports and
  unresolved rows are NULL — they have no local path to compare.
- The `##marker` lines in probe.sh output are the parse contract between
  collection and parsing — change them on both sides together.
- The first `uv` run bootstraps into `~/.local/bin`; the project
  remains stdlib-only, so `uv run python` needs the venv but no packages,
  and parse runs work fully offline.
